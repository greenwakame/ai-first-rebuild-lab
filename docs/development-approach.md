# 開発の進め方

このプロジェクトの最大の特徴は、対象領域そのものよりも**開発の進め方**にあります。ここでは4つの柱を説明します。

## AI-first開発

このプロジェクトは、AIコーディングエージェント（Claude Code、Codex）による実装を前提に設計されています。人が毎回同じ説明を繰り返さずに済むよう、共通指示を1か所に集約する構造を採っています。

- **`AGENTS.md`** を、エージェントへの共通指示の唯一のソースとしています。ミッション、リポジトリ境界、アーキテクチャ境界、作業手順、データ・セキュリティ方針、検証基準、コードレビュー基準をここに集約します。実物は [reference/agents-md.md](reference/agents-md.md) を参照してください。
- 繰り返し行う手順は **`.agents/skills/`** に切り出しています。Issue駆動の実装フロー、PRの検査、データベースマイグレーション管理、機能スライスの計画、セキュリティレビュー、UI検証など、6つのskillを運用しています。実物の紹介は [reference/skills.md](reference/skills.md) を参照してください。
- Claude Code と Codex の両方に対応するアダプタ構造を採っており、どちらのエージェントを使っても同じ`AGENTS.md`・同じskillsを参照します。

AIが生成した差分をそのまま信頼するのではなく、**生成された差分を人が検証する**ことを前提にしたプロセス設計にしています。

## ADR駆動

元に戻しにくい判断は、必ずADR（Architecture Decision Record）として記録します。「なぜその設計にしたか」を後から追えるようにすることが目的です。

- コンテキスト（何が問題か）、決定（何を選んだか）、その根拠を1つの文書にまとめます
- 判断が改訂された場合は、元のADRに改訂履歴を追記し、新しいADRとの相互参照を残します
- 実績として21件のADRを記録しています。実物は [adr/](adr/) を参照してください

ADRは、このプロジェクトの技術的な議論の質を最も直接的に示す資料だと考えています。

## 契約優先

Rust APIとNext.jsの境界はOpenAPIドキュメントを正とし、そこから型を自動生成し、CIで契約とコードの乖離を検査します。詳細は [architecture.md](architecture.md) を参照してください。

## 検証文化

「コードが生成されただけでは、タスクは完了していない」ことを明文化しています。

- 現在のworktreeで実行に成功していないチェックを、合格したと主張しない
- テストは意味のある最も低いレイヤーで行い、ユーザーに見える振る舞いにはサービス横断・E2Eのカバレッジを追加する
- マイグレーションでは、スキーマ・行数・キー関係・代表的なチェックサムを比較する（実データの値は露出しない）
- UI変更では、loading・空状態・エラー・権限拒否・狭い画面幅の状態を確認する
- 必要なチェックが実行できない場合は、具体的な障害要因を説明し、再現可能な次のコマンドを残す

日常のコマンド実行は `mise run <task>` に集約しており、「手元でこのコマンドが通った」という事実だけを根拠に完了を主張する運用にしています。

## 供給網の扱い

skills、hooks、MCPサーバー、CIワークフロー、依存関係スクリプトは、いずれも**実行可能な攻撃面**として扱います。有効化する前に、実行内容と認証情報のスコープをレビューします。これはAIエージェントに強い実行権限を与える構成である以上、通常のコードレビュー以上に供給網のレビューを重視する必要があるという判断によります。
