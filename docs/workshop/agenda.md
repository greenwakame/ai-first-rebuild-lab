## 2. privateリポジトリへの招待

当日限定の一時アクセスをお渡しします。招待を受諾してください。

## 3. 環境構築

事前準備（[prerequisites.md](prerequisites.md)）が済んでいる前提で、次を実行します。

```bash
git clone <招待されたリポジトリのURL>
```

```bash
brew bundle
```

```bash
mise install
```

```bash
mise run doctor
```

`mise run doctor` が通れば環境構築は完了です。

> [!WARNING]
> ここでつまずいた場合はサポートしますが、**事前準備を済ませてきていただくことが最大の時間短縮になります。**

## 4. Issue選定

当日取り組めるIssueを用意しておきます。その中から、興味のある領域・使いたい言語に合わせて選んでください。

| 観点 | 内容 |
| --- | --- |
| **領域** | Next.js（UI）、Rust（API）、PostgreSQL（スキーマ・認可）、ドキュメント |
| **規模** | 半日で着手からPR提出まで到達できるもの |

> [!IMPORTANT]
> 選んだIssueについて、着手前に**何を達成すれば完了なのか**を合意します。これはこのプロジェクトの進め方の中核です。**Issueの完了条件が曖昧なまま実装を始めません。**

## 5. 実装

AIコーディングエージェント（Claude Code / Codex）を使って実装します。

このプロジェクトでは、エージェントへの共通指示を `AGENTS.md` に集約し、繰り返す手順を `.agents/skills/` へ切り出しています（[agents-md.md](../reference/agents-md.md) / [skills.md](../reference/skills.md)）。エージェントはこれらを読んだ上で作業します。

> [!IMPORTANT]
> **重要な点は、生成された差分を自分で読んで検証することです。** 「エージェントが書いたから正しい」とは扱いません。

## 6. 検証

実装したら、リポジトリの検証コマンドを実行します。

```bash
mise run check
```

UIを変更した場合は、加えて次を実行します。

```bash
mise run check:ui
```

「現在のworktreeで実行に成功していないチェックを、合格したと主張しない」という原則があります。**通らなかったものは通らなかったと記録します。**

## 7. Pull Request の提出

日本語でPull Requestを書きます。含めるのは次の内容です。

- [x] 何を変更したか
- [x] どの検証を実行し、何が成功したか
- [x] **確認できなかったことは何か**

> [!NOTE]
> 最後の項目を省略しないことが、このプロジェクトのPRの特徴です。実際の例は [issue-walkthrough.md](issue-walkthrough.md) を参照してください。

## 8. レビュー

提出されたPull Requestを、その場でレビューします。設計判断の背景、検証の考え方、なぜこの粒度でIssueを切るのかといった観点を共有します。

マージは当日中とは限りません。レビュー内容によっては追加の修正をお願いすることがあります。
