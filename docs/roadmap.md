# ロードマップ

現在地と、今後のフェーズを示します。開発は別のprivateリポジトリで継続しており、ここでは進捗の区切りだけを共有します。

## フェーズ

### Phase 0: 現状調査 — 完了

旧システムの構成、依存関係、画面、API、データベース設計、運用を調査し、セキュリティ・再現性・データ移行のリスクを抽出しました。

### Phase 1: セキュリティ封じ込め — 完了

旧システムに含まれていた鍵・証明書・資格情報を棚卸しし、失効・ローテーションしました。個人情報を含む可能性がある文書・データを隔離し、取り扱い方針を確定しました。

### Phase 2: 基盤ブートストラップ — 完了

- AIコーディングエージェント向けの共通指示（`AGENTS.md`）と、再現可能な手順（skills）を整備
- Homebrew + mise による再現可能なCLI環境
- Next.js、Rustワークスペース、Supabaseローカルスタックの最小起動
- lint・format・test・buildを検証するGitHub Actions
- Vercel preview、Render staging、Supabase stagingのデプロイ基盤

### Phase 3: 仕様固定とデータ基盤 — 完了

- 主要ユーザーフローの仕様を固定し、検証可能な形で文書化
- 旧データベーススキーマをPostgreSQLへ変換する設計を確定
- 外部キー・制約・インデックス・監査列を設計
- 移行時の行数・チェックサム・キー関係の検証方法を確立

### Phase 4: 最初の縦切り — 完了

ログインとメンバー一覧を、認証・認可・データ・画面を通した最初の参照実装として完成させました。

- Supabase Authによるログイン・ログアウト・セッション維持
- Next.jsのサーバー境界から認証済みRust APIへの接続
- 認可済みメンバーの一覧・検索・並び替え・ページング
- loading・0件・入力エラー・権限エラー・upstream errorの区別
- 狭い画面幅・キーボード操作・基本的なaccessibilityの検証
- 認証後の共通UI（AppShell）とデザイン基盤の確立

旧機能は存在することだけを理由に再実装せず、機能単位で「踏襲・改善・廃止・保留」に分類し、判断根拠を記録してから実装する方針を採っています。

### Phase 5: 業務機能移行 — 進行中

メンバープロフィール詳細、自己紹介、プロフィール写真、スキル・資格などを、縦切り単位で移行しています。各機能は「根拠確認 → データベース移行 → API契約 → UI → E2E → 利用者確認」を1単位としてリリースします。

### Phase 6: 移行リハーサルと切替 — 未着手

本番相当データでの移行リハーサル、権限・データの照合、ロールバック手順の確認、段階公開を予定しています。

## 現在地

Phase 5が進行中です。並行して、このリポジトリを含む「誘致・ワークショップ向けの公開入口」の整備も進めています。

## 移行中の非交渉事項

- 旧リポジトリの秘密情報・証明書・実データ・画像アーカイブを新リポジトリへコピーしない
- 匿名化されていない本番データをローカル開発やCIに使わない
- 認証だけ、データベースだけ、画面だけを一括切替しない。検証可能な縦切りで進める
- 手作業で生成した成果物をGitにコミットしない
- デプロイ・マイグレーション・ロールバックはCLIとCIで再現可能にする
- 現行の独自認可を理解せずに単純なロールへ置換しない
